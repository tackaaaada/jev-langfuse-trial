# 意味的一致ベンチマーク v0（10件）

2026-09-19に、[10件の合成データ](../data/semantic_equivalence_v0.json)をJevあり・なしの両条件で各1回ずつ評価しました。ベンチマークIDは`YOUR_PRIVATE_ID`です。

## 条件

- **Jevあり**: Jev `jev-latest`が`semantic_match`確率を返し、0.5以上を一次trueとする。`finalize-answer`のmetadataにこの`jev_result`を保存し、`Check Correctness`（GPT-4o）が回答・期待回答・Jev結果・評価プロンプトを受け取る。
- **Jevなし**: Jevを呼び出さない。`finalize-answer-without-jev`に同一の回答・期待回答を保存し、`Check Correctness Without Jev`（GPT-4o）が回答・期待回答・評価プロンプトを受け取る。
- **人手ラベル**: 各データの`expected_match`は比較用にmetadataへ保存するが、どちらのEvaluatorの変数マッピングにも渡さない。
- **評価プロンプト**: 両条件で意味的一致の基準は同じ。Jevありだけが、Jev結果を参考情報として独立に判断する指示を含む。

実行コマンドは`uv run python -m src.semantic_equivalence_benchmark --condition both`です。Jevを10回、LangfuseのマネージドEvaluatorを20回呼び出します。

## 読み取れること

10件では、Jev、JevありGPT-4o、JevなしGPT-4oのいずれも、人手ラベルと9/10件で一致しました。内訳は真陽性6、真陰性3、偽陽性1、偽陰性0です。正解率は90%ですが、データはこの実験のために手作業で作成した小標本であり、性能指標として一般化できません。

両GPT-4o条件は10件すべて同じ最終判定でした。この範囲では、Jev結果を渡したことによる最終true/falseの変化は観測されませんでした。JevありのEvaluatorがJev結果を参照しても、独立に判定できていることを直接証明する実験ではありません。Jevの判定を意図的に反転させた合成対照や、JevとGPT-4oが実際に異なり得る難例を別途用意して検証する必要があります。

唯一の不一致は`unsupported-shipping-claim`です。期待回答にない「すべての注文で追跡番号と置き配が自動的に利用できる」という主張を、3系統すべてが意味を変えない追加情報としてtrueにしました。人手ラベルでは、根拠のない配送条件は重要な追加主張なのでfalseとしています。

評価プロンプトには「矛盾せず意味を変えない追加詳細は許容」と「根拠のない主張はfalse」の両方があります。この難例では前者が強く解釈されたため、追加主張の扱いを明確にするプロンプト改善候補になりました。たとえば、期待回答から導けない運用条件・権利・制約を追加した場合は、矛盾がなくてもfalseと明記し、正例・負例を追加して再評価します。

## 限界と次の校正

- 各ケースは1回ずつで、Evaluatorの出力の揺れは測っていません。
- 同一の人が設計・ラベル付けした合成データであり、実運用データでも独立の人手ラベルでもありません。
- Jevの閾値0.5は未校正です。今回の結果だけで閾値を変更しません。
- 次は境界例を増やし、少なくとも独立レビューのラベルとエラー分類を付けた固定テストセットで、プロンプト変更前後を比較します。
